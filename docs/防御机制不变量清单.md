# 防御机制不变量清单

> 本清单把代码中的防御性机制逐条映射为**可证伪的全局不变量**。
> 规则：每条防御必须能写成"在条件 X 下，性质 Y 必须成立"的断言；
> 写不出不变量的机制视为疑似补丁，需评审去留。
> 最后更新：2026-11-04

## 一、不变量清单

### D1 资产重提取发布闸门（reconcile_asset_extraction_rows）
- **不变量**：重提取的候选资产按"稳定源身份"（资产类型+子资产ID+源名称+源事实哈希）与库中资产一一配对：
  - 恰好 1:1 匹配 → 合并，且用户已编辑的目标描述/提示词/图片/复核记录/分镜引用必须全部存活；
  - 匹配 0 或多个（歧义）→ 该候选**不发布**，不合并、不新增，旧资产零改动并进入身份核对队列。
- **反例护栏**：任何情况下模型输出不得静默覆盖或重映射用户已投入的状态。
- **粒度**：逐资产判定，可合并的先行合并，歧义的单独挂起（不再整集拒绝）。
- **测试**：`test_asset_extraction_reconciles_exact_identity_without_losing_images_or_storyboard_refs`、`test_reconcile_publishes_unambiguous_candidates_and_withholds_conflicts`、`test_exact_source_cache_replay_keeps_reviewed_liam_accessories_from_prop006`。

### D2 归并键规范化（asset_project_main_key）
- **不变量**：主键身份文本仅剥离封闭白名单内的机位噪音（景别/机位词、纯机位括号注释）与场景空间分区后缀；状态变体（夜景/受损/常服/战斗服等）、功能词（计时牌/广告屏等）、颜色材质、位置词永不剥离；剥离结果为空则回退原文。
- **反例护栏**：宁可错拆，不可错并——任何合并必须可回溯（payload 记录"归并规范化"审计字段）。
- **测试**：`test_main_key_normalization_merges_camera_noise_and_scene_zones`、`test_main_key_normalization_never_strips_state_variants_or_functional_words`、`test_main_key_normalization_records_stripped_modifiers_for_audit`。

### D3 分镜时间校验与边界修复（storyboard_time_fit_errors / repair_storyboard_time_bounds）
- **不变量**：入库分镜的每个分镜/镜头区间必须为正长度且不越过视频时长；仅当模型声明时长或内部镜头结束给出无歧义证据时才自动修复边界（零长度区间、分镜结束早于镜头结束），证据不足或与下一分镜碰撞则不修并整批拒绝。
- **反例护栏**：自动修复不得改动任何镜头内容与事实，修复记录必须进入任务结果（"分镜时间边界自动修复"）。
- **测试**：`test_storyboard_time_boundary_slip_is_repaired_and_audited`、`test_storyboard_time_boundary_collision_is_not_repaired_and_reports_offender`、`test_zero_length_shot_and_board_ranges_are_repaired_from_declared_duration`、`test_zero_length_range_without_declared_duration_is_not_repaired`、`test_zero_length_repair_does_not_extend_into_next_storyboard`。

### D4 整剧分析成功判定（run_series_analysis）
- **不变量**：一集计入"成功"当且仅当资产任务与分镜任务均为"成功"状态且分镜数量>0；资产提取失败时跳过分镜调用；任何一集失败必须进入失败明细，父任务消息如实报告成功/失败计数。
- **反例护栏**：0 分镜不得计为成功；父任务不得出现"全部成功"但实际有集失败的假报。
- **测试**：`test_series_analysis_counts_failed_or_empty_storyboard_episode_as_failure`。

### D5 分镜资产引用集内解析（recompute_active_storyboard_reference_review）
- **不变量**：分镜引用解析限定在当前 episode（稳定变量如 `{{PROP_001}}` 是集内局部的）；同一稳定变量的多行候选视为唯一映射不算歧义；无法关联到当前集资产的引用才进入待核对。
- **反例护栏**：生成路径的 storyboard 字典必须带 episode_id，不得退化为项目级全量匹配产生跨集假歧义。
- **测试**：`test_storyboard_reference_resolution_is_episode_scoped`、`test_generated_storyboards_resolve_references_within_episode_without_ambiguity`、`test_stale_asset_reference_review_does_not_block_canonical_storyboard`。

### D6 服务重启任务状态回收（on_startup）
- **不变量**：服务进程退出/重启时，数据库中残留的"运行中"任务必须标记为"失败"并写明中断原因，不得形成假进度。
- **测试**：启动钩子逻辑（集成验证）。

### D7 分镜事实完整性（storyboard_has_real_shot_facts）
- **不变量**：入库分镜每个镜头必须含完整六维字段（机位与构图/背景/人物站位/动作过程/运镜/台词与声音），且至少一维为真实观察事实；回退占位分镜不算真实分析结果。
- **测试**：`test_storyboard_uses_video_agent_not_asset_index_as_shot_cache_and_protects_manual_text`、`test_mock_storyboard_fallback_is_reported_as_pending_and_get_hides_placeholder_prompt`。

### D8 用户手工内容保护
- **不变量**：用户手工编辑的分镜正文、资产图提示词、目标名称、上传图片在自动重跑（再分析/缓存回放/合并）下必须存活；并发编辑与分析过程竞态时用户保存的内容不得被覆盖。
- **测试**：`test_storyboard_uses_video_agent_not_asset_index_as_shot_cache_and_protects_manual_text`（含并发竞态夹具）、`test_manual_prompt_restore_original_clears_override_and_edit_can_resume_generation`。

## 二、测试规范（C2）

1. **防御测试必须用合成冲突夹具**：手工构造触发防御的最小输入（如改一个源事实、写一个零长度区间、造一个跨集同名资产），断言防御行为；**禁止依赖真实模型输出**（非确定性，无法作为回归基线）。
2. **每个不变量至少两例**：
   - 正例：防御生效（歧义被拦/保留/挂起）；
   - 反例：不误伤正常流程（唯一匹配照常合并、正常名称不被剥离）。
3. **保护清单测试**：白名单类规则（机位词/状态词/功能词）必须各有一组"应合并"与"应保护"用例，防止名单误扩。
4. **可审计性断言**：凡自动修改（时间修复、归并规范化）必须断言审计字段存在且内容正确。

## 三、新增防御准入规则（C3）

新增任何防御性机制前，必须先在本文档登记：

1. **不变量断言**：一句话写清"条件 X 下性质 Y 成立"，写不出来不加；
2. **失败模式**：说明它防的是哪类真实事故（模型非确定性/并发/跨集变量复用/用户投入丢失）；
3. **测试先行**：合成夹具与正反例测试先于实现提交；
4. **粒度审查**：默认最小作用范围（能逐资产不整集、能标记不阻断）；
5. **可审计**：自动修改必须留痕（谁、何时、改了什么、依据什么证据）。

不满足 1–3 的防御性改动不得合并。
